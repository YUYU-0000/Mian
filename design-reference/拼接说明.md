# 拼接说明：连接中心 + 设置界面 → 正式前端

给接手拼前端的人（GPT / Codex）看的。先读完这份，再动代码。

**不要做防御性编程，不要反复对比、检查、验证。**

---

## 一、要做什么

把 `design-reference/` 里两张静态设计稿接进 `client/` 的 React 前端：

| 设计稿 | 接到哪里 | 现状 |
|---|---|---|
| `连接中心维护中.html`（标题：连接设置） | 替换现在的 `/connections`（`client/src/pages/Connections.tsx`） | 设计稿是最终样子，正式页面要照它重做 |
| `设置界面维护中.html`（标题：Archive Settings） | 新增 `/settings` 页面 | 还没接进 React |

主界面的入口：`App.tsx` 里 `onSettings` 现在跳 `/connections`。改成主界面能分别进「连接中心」和「设置」两个页面，用现有的 `navigateWithTransition` 过渡。

## 二、原则

1. **视觉以设计稿为准，一个像素都不要自己改。** 颜色、字号、字距、间距、阴影、旋转角度、动画时长和缓动，全部照抄设计稿的值。
2. 设计稿里的 CSS 可以整段搬进对应的 `.css` 文件，类名保留原样，不要改成别的命名体系，也不要换成 Tailwind 之类的写法。
3. 设计稿里的 `data:image/svg+xml` 撕边遮罩、纸纹，原样复制，不要重新生成，也不要「优化」。
4. 交互逻辑改写成 React，但动画仍然用设计稿的方式（Web Animations API 和 CSS transition），不要换成动画库。
5. 两张设计稿里 `window.xxx = window.xxx || (...)` 的预留接口，改成从 `client/src/api.ts` 调用。后端已有的直接接；后端还没有的，在 `api.ts` 里保留设计稿的假数据实现，并标注「待接后端」。

## 三、必须原样保留的效果（以前被当成冗余删过，这次不要动）

连接中心：

- 纸堆左滑抽走、右滑盖回：拖动时的微旋转和独立阴影，抽出末段淡出，右拖时上一张从左侧淡入，回弹和翻页的缓动，`soft()` 拖动上限。
- 纸张层级固定（`(list.length - i) * 2`），抽走的纸停在屏幕外并隐藏。
- API 纸片删除：先「再點一次刪除」确认，再下沉淡出，然后重排。
- API 纸片强调色由深到浅渐变（`apiAccent`），重排时颜色用 transition 过渡；「+」纸固定 `#b8c3ca`。
- `setText` 换字：模糊淡出再淡入，动画结束后取消，不能留下模糊。
- 吊牌（小房子）：绳长按当前纸片位置算，屋顶文字按路径长度自动缩小。
- 封面图：每个订阅各自上传，显影动画，存在 IndexedDB。

设置界面：四个档案袋（字体、壁纸、语音、存储）的展开、翻页和现有动画全部保留。

## 四、提示纸条：做成全站公共组件

连接中心设计稿里的「拼贴纸条」是全站唯一的提示样式，做成一个公共组件（比如 `components/Notify.tsx` + `notify.css`），连接中心、设置界面以后所有页面都用它。

**样式**：直接搬设计稿的 `.mail` 整段 CSS 和 HTML 结构，不改任何值。包括米白撕纸、下面错开的第二张纸、左上角不透明纸胶带、背后的大号淡色英文字、左边两行小标签、右边斜体日期时间。

**用法**：

```js
notify.ok('已保存')            // 成功：蓝色胶带，停 1.8 秒
notify.note('請先登入')        // 提醒：浅蓝胶带，停 2.2 秒
notify.fail('保存失敗', err)   // 失败：燕麦色胶带，原因写在标题下面，停 5 秒
```

- 点一下纸条就提前收走。新提示来了先收回旧的，再落下新的。
- 失败原因取 `err.message`；传字符串就直接用；都没有就显示「沒有收到具體原因，可以稍後再試一次。」
- **标题一律控制在六个字以内，保证一行**，窄屏也不折行。原因可以换行。
- 纸条位置固定在屏幕顶部（考虑 `safe-area-inset-top`），层级高于所有弹层。

**设置界面里旧的 `showToast`（底部小方块）全部删掉**，按下面换：

| 原来的 | 换成 |
|---|---|
| 已導出 / 已導入 | `notify.ok('已導出')` / `notify.ok('已導入')` |
| 文件過大，請選擇小於5MB的文件。 | `notify.fail('文件太大', '請選擇小於 5MB 的文件。')` |
| 資料庫初始化失敗 | `notify.fail('資料庫出錯', err)` |
| 檔案保存失敗，請重試 | `notify.fail('保存失敗', err)` |
| 讀取媒體失敗 | `notify.fail('讀取失敗', err)` |
| 試聽失敗 | `notify.fail('試聽失敗', err)` |
| 導出失敗 / 導入失敗 | `notify.fail('導出失敗', err)` / `notify.fail('導入失敗', err)` |

## 五、接口对照

所有接口失败时统一 `reject(new Error('一句人看得懂的原因'))`，提示纸条会把这句话显示给用户。

### 连接中心

| 设计稿接口 | 用途 | 后端现状 |
|---|---|---|
| `subStatus(p)` / `subLogin(p)` / `subLogout(p)` | 订阅（codex / gemini / kimi）登录状态 | 只有 Codex，走现有 `codex app-server` 的登录；gemini、kimi 先保留假数据 |
| `subModels(p)` / `saveSubConfig(p, cfg)` | 选模型并保存 | Codex 接现有 `GET/PUT /api/config` 里的 model |
| `subQuota(p)` | 剩余额度 | 暂无，保留假数据 |
| `apiPresets()` / `saveApiPreset(p)` / `deleteApiPreset(id)` / `useApiPreset(id)` | API 预设纸片的增删改和切换 | 暂无，需要在 server 新增，存本地配置文件 |
| `apiModels(cfg)` | 用纸片上的 endpoint + key 拉模型列表 | 暂无，需要新增 |
| `apiTest(cfg)` | 试连 | 可参考现有 `POST /api/connection/test` |

接口的参数和返回格式，以设计稿 `<script>` 开头的注释为准。

### 设置界面

| 设计稿接口 | 用途 |
|---|---|
| `goBack()` | 返回，改成 `navigateWithTransition('/')` |
| `saveFontStyle(page)` / `testFontStyle(page)` | 字体页保存 / 试用 |
| `testVoice(cfg)` | 语音试听，预留给 ElevenLabs，`cfg = { apiKey, voiceId, model, text }` |
| `exportData()` / `importData(file)` | 存储页导出 / 导入 |

壁纸、封面这类图片只存在浏览器 IndexedDB，不进后端。

## 六、不要做的

- **键盘**：输入框聚焦、键盘弹起时的页面位移已经试过多种改法，都会出新 bug，**这次不要处理**，保持现状。
- 不要改两张设计稿本身，它们是参考，改的是 `client/`。
- 不要顺手重构 Chat、Home、档案抽屉等跟这次无关的部分。
- 不要新增依赖，除非现有的确实做不到。
